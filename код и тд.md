# Frontend Проект: Код И Тд

## 1. Краткое описание

Frontend проекта реализован в виде микрофронтовой архитектуры на базе `webpack` и `Module Federation`.

Текущая схема:

- `host` — оболочка приложения, маршрутизация, авторизация, navbar, fallback-экраны
- `remote-main` — основной пользовательский раздел со свайпом
- `remote-liked` — отдельный микрофронт для списка лайкнутых
- `remote-admin` — отдельный микрофронт для административного раздела
- `packages/shared-ui` — общий переиспользуемый UI и hooks
- `packages/webpack-config` — общий конфиг сборки для всех фронтов

## 2. Структура frontend части

```text

  host/
```

Файл: `apps/remote-main/src/exposes/AppRoutes.tsx`

```tsx
export default function AppRoutes() {
  const { availableProfiles, matches, handleLike, handleSkip, handleRestart, refetch } = useChan();

  return (
    <Routes>
      <Route
        path="swipe"
        element={
          <SwipeScreen
            chan={availableProfiles[0]}
            onLike={handleLike}
            onSkip={handleSkip}
            refetch={refetch}
          />
        }
      />
      <Route path="settings" element={<ProfileSettingsPage />} />
      <Route
        path="finish"
        element={
          <div className="px-4 py-10">
            <FinishScreen
              matches={matches}
              total={Math.max(availableProfiles.length + matches.length, 1)}
              onRestart={handleRestart}
            />
          </div>
        }
      />
      <Route path="*" element={<Navigate to="swipe" replace />} />
    </Routes>
  );
}
```

```tsx
export default function AppRoutes() {
  const { authFetch } = useAuthContext();

  const handleSkip = async (profile: Chan) => {
    try {
      const response = await authFetch(`${API_BASE_URL}${ROUTES.girls.unlike(profile.id)}`, {
        method: "DELETE"
      });

      if (!response.ok) {
        throw new Error("Не удалось убрать карточку из лайкнутых");
      }
    } catch (error) {
      console.error(error);
    }
  };

  return (
    <Routes>
      <Route path="*" element={<LikedPage onSkip={handleSkip} />} />
    </Routes>
  );
}
```

## 9. Обработка отказа микрофронта

Файл: `apps/host/src/components/MicrofrontendBoundary.tsx`

Идея:

- host пытается подключить remote через `lazy`
- если remote не успел подняться, используется `importWithRetry`
- при окончательной ошибке показывается дружелюбный fallback
- пользователь может повторить попытку без перезагрузки всей страницы

Фрагмент:

```tsx
const RemoteComponent = useMemo(() => lazy(loader), [loader, retryToken]);

const handleRetry = useCallback(() => {
  setIsRecovering(true);
  setRetryToken((current) => current + 1);
}, []);
```

## 10. Авторизация и стабильность сессии

Файл: `packages/shared-ui/src/hooks/useAuth.ts`

Что реализовано:

- access token / refresh token хранятся в `localStorage`
- при `401/403` автоматически вызывается refresh
- обновленные токены синхронизируются между вкладками
- исключены гонки при одновременном refresh в нескольких запросах

Фрагмент:

```ts
const refreshPromiseRef = useRef<Promise<string | null> | null>(null)
```

```ts
if (refreshPromiseRef.current) {
  return refreshPromiseRef.current
}
```

## 12. Итог

В проекте frontend реализован как набор независимых приложений, объединенных через `webpack module federation`.

Плюсы текущей схемы:

- можно независимо останавливать и запускать отдельные разделы
- host остается живым, даже если один из микрофронтов недоступен
- общий UI и логика переиспользуются через `shared-ui`
- раздел `liked` теперь вынесен в отдельный микрофронт и может обслуживаться независимо от `remote-main`
